# Obsidian Memory System

Use Obsidian as your external memory. Every lesson learned, pattern discovered, or insight gained should be captured in your vault for future reference and compounding knowledge.

## ZED Subheader

All notes must be written under a `## ZED` subheader. This keeps your notes organized and clearly attributed to your work as the Zed agent. Never write notes outside this section.

Structure each note as:
```
## ZED

### [Topic or Pattern Name]
- **Date**: YYYY-MM-DD
- **Context**: What you were working on
- **Lesson/Pattern/Insight**: The key takeaway
- **Tags**: #relevant #tags
```

## Maintenance

Regularly review and maintain your notes:
- **Purge superseded notes**: When a lesson is updated or a pattern evolves, remove or archive the old version
- **Consolidate related notes**: Merge similar insights into a single, comprehensive note
- **Update outdated information**: Keep notes current with the latest understanding
- **Remove duplicates**: Ensure each insight appears only once

Keep the vault lean and valuable. Old, superseded notes create noise.

## When to Write to Obsidian

- After solving a non-trivial bug
- After discovering a useful pattern or technique
- After learning something unexpected about the codebase
- After a failed approach that revealed important constraints
- After completing a significant refactor or feature
- When you notice a recurring theme across multiple tasks

## What to Capture

### Lessons Learned
- What went wrong and why
- What the root cause was
- How to prevent it next time
- What signals to watch for

### Patterns Discovered
- Code patterns that work well
- Architectural decisions and their rationale
- Testing strategies that proved effective
- Debugging techniques that succeeded

### Insights Gained
- Non-obvious connections between components
- Performance characteristics
- Edge cases and boundary conditions
- User behavior patterns

### Project Knowledge
- Key decisions and their context
- Technical debt and its implications
- Integration points and dependencies
- Deployment and operational considerations

## How to Structure Notes

Use clear, searchable titles. Include:
- **Context**: What were you working on?
- **Problem**: What was the challenge?
- **Solution**: What worked (or didn't)?
- **Lesson**: What's the takeaway?
- **Tags**: Use consistent tags for related topics

## Obsidian Integration

- Link related notes together
- Use tags consistently (e.g., #pattern, #bug, #lesson, #architecture)
- Reference specific files or code when relevant
- Update existing notes when you learn more about a topic
- Review and refine notes periodically

## The Compound Effect

Each note is a building block. Over time:
- Patterns emerge across notes
- Connections become visible
- Knowledge compounds
- Future problems become easier to solve

Your Obsidian vault is your external brain. Use it deliberately.
